# Documentation

This documentation follows the [Diátaxis](https://diataxis.fr/) framework, which
organises content into distinct categories based on the reader's need. Each
folder serves a specific purpose:

| Folder | Purpose |
| ------ | ------- |
| [`0-overview`](./0-overview) | High-level introduction to the project: what it is, why it exists, etc. |
| [`1-concepts`](./1-concepts) | **Explanation** — background and conceptual material that helps the reader *understand* the project and the ideas behind it. |
| [`2-how-to`](./2-how-to) | **How-to guides** — goal-oriented, step-by-step instructions that help the reader *accomplish a specific task*, including operational tasks such as deployment, monitoring, runbooks, and day-to-day running of the system. |
| [`3-references`](./3-references) | **Reference** — precise, factual descriptions of the system (APIs, configuration, commands) for *looking things up*. |
| [`4-specifications`](./4-specifications) | Detailed specifications, design decisions, and formal requirements for the project. |

## About Diátaxis

Diátaxis identifies four modes of documentation — **tutorials**, **how-to guides**, **reference**, and **explanation** — each addressing a different user
need. Keeping these modes separate makes documentation easier to write, find,
and maintain. See <https://diataxis.fr/> for more details.
